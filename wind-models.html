局部相对风 → 旋翼力 → 合力矩

计算链：从m/s到N，再到N·m

以下统一记号与六旋翼写法是接入方案，非照抄四旋翼的坐标或分配矩阵。R将机体系旋转到世界系；v为参考点速度，Ω为机体系角速度；rᵢ为参考点到第i个旋翼的机体系位置，aᵢ为其单位推力轴。

1. 计算各旋翼处相对气流

uᵢᵇ = Rᵀ [W(xᵢ,t) − v] − Ω × rᵢ
u∥,ᵢ = aᵢ · uᵢᵇ
u⊥,ᵢ = uᵢᵇ − aᵢ u∥,ᵢ

若有倾转机构，应使用实际旋翼轴；若旋翼安装点相对机体运动，还需减去该点相对速度。若模型原点和刚体质心不同，v、r和最终力矩必须一起转换到同一参考点。

2. 最易落地：机身二次阻力

Fbody = ½ ρ Cᴅ A ‖u‖ u
τbody = rCP × Fbody

第一式对应Craig式4.38的机身钝体项；第二式是力矩合成的工程补充。ρ为空气密度，CᴅA为等效阻力面积，rCP是压力中心相对施力参考点的偏移。若力穿过参考点，力臂项为零；不能由“20 N”单独推出“0.2 N·m”。非球形机身可按姿态/入流方向标定CᴅA；机械臂和载荷需额外考虑。

3. Jeon路线：旋翼横向力与轴向修正

Tᵢ = kω ωᵢ² + kz u∥,ᵢ ωᵢ + kh ‖u⊥,ᵢ‖²
Hᵢ = c Tᵢ u⊥,ᵢ
Frotor = Σᵢ (Tᵢ aᵢ + Hᵢ)
τrotor = Σᵢ [rᵢ × (Tᵢ aᵢ + Hᵢ) + sᵢ kₘ Tᵢ aᵢ]

前两式核对自Jeon学位论文式5.12、5.13；求和写法是我们对任意旋翼布局的推广，需按六旋翼的轴向和旋转符号sᵢ重新验证。kω、kz、kh、c、kₘ需要本平台标定。ω必须注明rad/s或rpm；论文实验拟合使用rpm，不能直接把系数与rad/s混用。由H=cTu可知c应具有s/m量纲；不照搬表格系数或单位。

建议先实现降阶横向项：Hᵢ=cᵢ Tᵢ,actual u⊥,ᵢ。现有真实推力可以直接用于该项，暂不声称复现Jeon完整BEMT。完整轴向修正必须先补真实转速标定，并处理零转速/大入流等失效区；公式不是无限风速下都可信的推力来源。

4. Craig路线：补充桨叶挥舞产生的桨毂力矩

Mhub,ᵢ ≈ (Nblade / 2) kβ βmax (cos φD u₁ + sin φD u₂)
总力矩 = Σᵢ [rᵢ × Fᵢ + Mhub,ᵢ + 旋翼反扭矩ᵢ]

桨毂项对应Craig式4.5：需要挥舞刚度kβ、挥舞幅值βmax、相位φD及局部流向基u₁/u₂；β和入流、转速、桨叶几何及动力学有关。文中的四旋翼对转抵消式4.6不能直接套到六旋翼。只做机身阻力会漏掉这类不等同于r×F的气动力矩。

Kaimal层：生成风速，而不是直接生成力

W(x,t) = W̄(x) + u′(x,t) + Wgust(x,t)
Sₖ(f) = [4 σₖ² Lₖ / Ū] / [1 + 6 f Lₖ / Ū]^(5/3)
∫₀∞ Sₖ(f) df = σₖ²             TI = σu / Ū

这里S为单边功率谱，f单位Hz，Ū、σ单位m/s，L单位m；公式来源为TurbSim v2的IEC Kaimal式23，不标为1972原式。可先用频谱合成生成固定seed长序列，再按仿真时间采样。积分尺度L调“涡尺度/变化时间”，σ或TI调波动幅值，Ū调平均来流；独立阵风另设幅值和时长。

  • 悬停不等于空气不流动：平流速度应与平均来流有关，不能把无人机地速0直接填入分母。Ū接近0时此形式需另外建模，不能靠随意加小常数假装物理正确。
  • 空间相干：每个旋翼完全独立白噪声会制造不合理力矩；先全机共享来流，再按长度尺度/相干模型扩展到旋翼采样点。Kaimal单点谱本身不唯一确定跨点或跨分量相关性。
  • 不等于建筑绕流：近墙、柜内、地面约1m高度不能直接套用风机轮毂尺度的IEC参数。若要真实遮挡、回流和尾流，应另用实验场或CFD/LES离线场。
  • 验证：长序列检查均值、方差、PSD和相关时间；空间版本检查互谱/相干。20秒录像不足以验证低频湍流统计。

数量级计算器：20 N并不对应唯一风速

仅展示机身二次阻力与垂直力臂关系。所有默认几何/系数是假设示例，未标定到我们的飞机；不包含旋翼气动，不代表测评结果。

代数计算 · 非Isaac仿真

力臂必须垂直于力才有τ=rF；任意方向用叉积。平移风速、气动系数、迎风面积和旋翼工作状态都影响实际结果。

接入现有Isaac：底层接口够用，上层模型要补

已有能力（本地源码核对）可复用必须补齐/注意
RobotIO.apply → permanent_wrench_composer.set_forces_and_torques接收合力和合力矩，指定control_body_idx；默认非全局坐标保持控制命令与新增气动项相加；不能覆盖已有力。风模型用world，施力前转body。
WindWrenchAdapter与composer回读审计每步120Hz，实际新增F/τ回读、独立seed、显式reset当前输入是预定义wrench。新版本要每步读取v、Ω、R、旋翼状态，让气动力随实际状态变化；不能继续仅靠预生成F(t)。
旋翼布局、推力方向与actual motor_thrusts构造六旋翼Hᵢ与rᵢ×Fᵢ，使用限幅/动态响应后的实际推力RotorActuator暴露归一化转速，不是物理rpm/rad·s⁻¹。完整Jeon/Craig模型需转速标定或真实执行器模型。
现有线性阻力 F=-c vᵇ、地面/近墙旋翼修正可作为历史full背景保留不能再把完整新阻力和总推力加一遍。新模型与ground/wall修正的耦合需单独验证。

两种接入模式必须分开命名

保留旧full的增量模式：
Δwrench = Aero(state, W) − Aero(state, W=0)
command_new = command_old_full_without_legacy_wind + Δwrench

气动模型替换模式：
command_new = command_without_replaced_aero_terms + Aero(state, W)

增量模式便于控制变量，W=0时恢复旧背景，但它是混合模型，不等于完整复现论文。替换模式更自洽，却改变无风动力学，必须另做新基线验证；当前未执行。若加入总Tᵢ，先减掉已分配的原推力/反扭矩；若只加入Hᵢ及其力矩，不重复加入Tᵢaᵢ。

若力在压力中心或旋翼中心产生，先将合力矩统一到SDK实际施力参考点。需要核对质心与link原点偏移；不能在给positions的同时又重复加同一个r×F。仅旋转坐标不等于完成力矩参考点变换。

建议实施顺序（尚未执行）

  1. 确定坐标/力矩参考点、确认真实与归一化转速区别；建立原full气动项清单。
  2. 先做Kaimal单点风速＋可标定机身二次阻力＋压力中心力矩，明确它暂不含旋翼完整气动。
  3. 加入Jeon降阶横向力；取得转速/风洞数据后再扩展完整轴向修正与Craig挥舞。
  4. CPU验证：量纲、正负风向、90°姿态变换、无相对气流、同seed、谱方差、瞬时能量一致性。空间版本再检验相干。
  5. 另行批准后才做最小GPU悬停回归：检查W=0增量为零、旧full保持、实际composer回读和真实漂移。正式测评继续暂停。

结论：已有Isaac施力接口可以承接这些模型，短板是风速统计、参数标定及气动项的正确合成。20N/.2Nm只是此前的wrench诊断设定，不能作为气象模型标定目标，更不能靠放大风把所有控制器吹失稳来“证明真实”。
